# はじめに

> **3行で**
> 1. カードTRPG「カルタグラフ」を、まず紙で遊べるボードゲームとして設計している（コードはまだ書かない）。
> 2. 1回の作業＝1サイクル。AI が問いと推奨を出し、人間が「推奨で」か直しを答えて決める。
> 3. 再開するときは、[進み具合](index.md) と最新の[サイクルの記録](cycles/index.md)の「次に試すこと」を見て、AI に「サイクルを進めて」と頼む。

```text
フェーズ（外側から内側へ）
 0 下準備
 1 コンセプト
 2 紙のプロトタイプ
 3 試遊と調整
 4 ドメインモデル
 5 作るものを決める

1サイクル（1セッション）
 問いを選ぶ → 詰める
   → 確かめる → 決める
   → ふりかえる → 次へ
```

決めた結果は `design/`、理由は `decisions/`、作業の跡は `cycles/` に残る。いまどのフェーズかは [進み具合](index.md) にある。

以下は詳しく知りたいときに読む。

## 読む順

| 順 | 読むもの | 分かること |
|---|---|---|
| 1 | [進み具合](index.md) | いまのフェーズと、残っている終える条件 |
| 2 | [コンセプト](design/vision.md) | 何を届けるゲームか（決まったところまで） |
| 3 | [設計の進め方](process/index.md) | 1回の作業（設計サイクル）の回し方と、人間と AI の分担 |
| 4 | [サイクルの記録](cycles/index.md)の最新の1つ | 前回なにを決め、次に何をするつもりだったか（「ふりかえり」の「次に試すこと」） |
| 5 | [問い](questions.md) | まだ決めていないこと |

ここまでで再開できる。必要になったら、次を読む。

- [書き方](process/writing.md) — どこに何を書くか（1つのことは1か所に書く）
- [決定](decisions/index.md) — 決めた理由と、採らなかった案
- [用語集](design/glossary.md) — ゲームの言葉の意味
- [体制の進化ログ](process/evolution.md) — 進め方をどう直してきたか
- [前のリポジトリ](sources.md) — 参考資料の在りか

## AI との進め方

決まりの本文は [設計の進め方](process/index.md) にある。要点は次のとおり。

- **決めるのは人間。** AI は問いを立て、案を2〜3出し、推奨を添える。終える条件のチェックも人間が付ける。
- **AI は質問を番号付きでまとめて聞く。** 推奨に同意するなら「推奨で」と答えればよい。違うところだけ書く。
- **1回の作業＝1サイクル＝1セッション。** サイクルの終わりに AI が記録を書いてコミットする。次のサイクルは新しいセッションで始める。
- **進め方への不満は、そのまま言う。** AI が [体制の進化ログ](process/evolution.md) に書き、ふりかえりで採るかを決める。

AI への頼み方（Claude Code の場合。ほかのツールでは AI に `AGENTS.md` を読ませてから、同じことを頼む）。

| したいこと | 言い方 |
|---|---|
| 次の設計を進める | 「サイクルを進めて」 |
| 考えを詰めてもらう | 「詰めて」 |
| フェーズの終わりにふりかえる | 「ふりかえりをしよう」 |

## スマホで読む

PC で次を動かすと、同じ LAN のスマホのブラウザから `http://<PCのIP>:8000/` で `docs/` を読める。表示は [index.html](index.html)（docsify）が受け持つ。

```sh
python -m http.server 8000 --bind 0.0.0.0 --directory docs
```

PC の IP は `ipconfig` の「IPv4 アドレス」で分かる。つながらないときは、Windows のファイアウォールで Python を「プライベート ネットワーク」に許可する。
