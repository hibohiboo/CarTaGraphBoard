# DR-0008 やらないこと

- 状態：採用
- 日付：2026-11-01
- サイクル：[C3](../cycles/2026-11-01-C3-デザインの柱.md)
- 反映先：[コンセプト](../design/vision.md#やらないこと)

## 問い

魅力的だが、このゲームではやらないことは何か。柱を守るために捨てるものは。

## 決めたこと

次をやらない（PL 2人以上は [DR-0006](DR-0006-遊ぶ場面.md) で決めた）。

- 勝ち負けを競うこと（GM と PL の対戦、得点）。
- 遊ぶ前にルールを読み込む前提の、分厚いルールブック。
- GM が事前にシナリオを作ること。

数値・リソースの管理と、戦闘の細かさは、やらないことに入れない。

## 理由

- 勝ち負けを競わないのは、GM が白紙のカードを認める役（DR-0006）なので、GM が対戦相手だと認める判断が揺らぐため。
- 分厚いルールブックをやめるのは、遊ぶ気分「気軽に座って、思いつきを出すのが楽しい」（DR-0006）のため。
- GM の事前のシナリオ作りをやめるのは、シナリオの束を開けば遊べる形にし、ボードゲームとして設計しきるため。
- 数値・リソースの管理と戦闘は、AI は「細かい数値の管理」を、やらないことに入れるよう推奨した。人間の答えは「残したい。リソース管理も好き。ゲームブック形式にも似ている」。難しさは [DR-0007](DR-0007-デザインの柱.md) の柱2（計算は道具に任せる）で受ける。

## 採らなかった案

- **細かい数値の管理をやらない** — 人間がリソース管理を楽しみたい。セッションを止める重さは、道具で軽くする。
- **戦闘を精密に再現しない** — 同上。どこまで細かくするかは、前のリポジトリの仕分けで決める。

## 後で見直すとき

試遊で、数値や戦闘の計算が道具を使ってもセッションを止めると分かったとき。
