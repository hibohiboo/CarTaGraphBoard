# 体制の進化

> **3行で**
> 1. 進め方の気づきは、誰でも [体制の進化ログ](evolution.md) の候補に書き、ふりかえりで人間が採用／却下を決める。
> 2. 仕組みにするのは、同じ困りごとが2回起きてから。注意書きより、機械で止める仕組みを先に考える。
> 3. 進め方の文書は合わせて400行以内。足すときは、減らすものを書く。

遊んで育つゲームを作るのと同じく、進め方も気づきから育てる。

## 回し方

- **記録（誰でも）** — 「ルールが足りなかった」「邪魔だった」「話が通じなかった」に気づいたら、人間でも AI でも [体制の進化ログ](evolution.md) の候補に書く。
- **評価（人間が裁定）** — ふりかえりで、人間が採用／却下を決める。見る観点は、他のモデル・ツールでも回るか、1か所に書く決まり（SSOT）を壊さないか、手間に見合うか。
- **反映** — 採用したら `docs/process/` と `.claude/skills/` を直し、ログに日付・理由・きっかけを残す。却下も消さずに理由とともに残す。
- **仕組みにするのは2回目から** — 1回目の失敗は記録だけにする。同じ種類が2回起きたら、手順か仕組みにする。ただし、戻せない失敗（記録が消えるなど）は1回目から止める。
- **仕組みで止める** — 2回目の対策は、注意書きを足すより先に、機械で止める・自動で組み立てる仕組み（検査のスクリプト・git フック・Claude Code のフック）を考える。人や AI の注意力に頼る形は、担当やモデルが変わると崩れる。
- **楽観的に進める** — 前もって全部を防ごうとしない。後で気づいて戻せる失敗は、前で止める手順を足さない。

## 体制の重さの上限

前のリポジトリでは、進め方の文書と検査が中身より速く育ち、把握しづらくなった（[C0](../cycles/2026-11-01-C0-下準備.md)）。そこで重さに上限を置く。

- `docs/process/` の文書は、合わせて **400行以内**（`evolution.md` を除く）。超えそうなら、足す前に削るものを探す。
- 進め方を1つ足すときは、何を減らすか（減らせないなら、なぜか）を進化ログに書く。
- フェーズのふりかえりで、行数を確かめる（`wc -l docs/process/*.md`）。
