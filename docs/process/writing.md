# 書き方

> **3行で**
> 1. 1つのことは1か所に書き、ほかの場所からはリンクする（SSOT）。
> 2. 結論は `design/`、理由は `decisions/`、問いは `questions.md`、作業の跡は `cycles/`。
> 3. ページの冒頭には3行のまとめを置く。文は用語集の言葉で短く書き、仮のものは「（仮）」と書く。

## どこに何を書くか

1つのことは1か所に書き、ほかの場所からはリンクする。

| 書くこと | 置き場所 | 書き方 |
|---|---|---|
| ゲームの設計の結論（いまの正） | `docs/design/` | 現在形で、結論だけ。経緯・理由は書かず、決定へリンクする |
| 言葉の意味 | `docs/design/glossary.md` | 1語1項目。ほかのページは言葉を定義し直さない |
| 決めた理由と、採らなかった案 | `docs/decisions/DR-<番号>-<題>.md` | 1決定1ファイル。後から覆したら、新しい決定を作り、古いほうに「DR-xxxx で置き換え」と書く（消さない） |
| まだ決めていない問い | `docs/questions.md` | 1問1行。決めたら消して、決定へのリンクを残さない（決定のほうに問いを書く） |
| 1回の作業の記録 | `docs/cycles/` | 型は [サイクルの記録](../cycles/index.md)。後から直さない（記録なので） |
| 試遊の記録 | `docs/playtests/` | 型は [試遊の記録](../playtests/index.md) |
| ドメインモデル | `docs/model/` | フェーズ4から。`design/` を写したもので、ゲームのルールを新しく決めない |
| 進め方 | `docs/process/` | このページ・[設計の進め方](index.md)・[体制の進化ログ](evolution.md) |

設計のページ（`design/`）と記録（`cycles/`・`playtests/`）を分けるのは、設計のページを「いまの正」だけにして短く保つため。どう決まったかは記録と決定を辿れば分かる。

## 仮のもの

決めきれずに仮に置いたものは、設計のページで「（仮）」と書き、`docs/questions.md` に問いを残す。「（仮）」が付いたまま、フェーズを終えない（終える条件として確かめる）。

## ページの冒頭

- 読み物のページ（設計・進め方・各一覧の index）の冒頭には、`> **3行で**` のまとめを置く。読む人はまずここで概要をつかみ、詳細は続きを読む。
- まとめは本文の要約で、新しいことを書かない。本文を直したら、まとめも見直す。
- 記録（サイクル・試遊の各回）と決定（DR）の各ファイルには置かない。それ自体が短い。
- ページが長くなり話題が分かれたら、ページを分ける（目安100行）。

## 文の書き方

- 用語集の言葉を使う。同じものを別の言葉で呼ばない。新しい言葉が要るときは、先に用語集に足す。
- ルールは、遊ぶ人が読んでそのまま動ける文で書く。「誰が」「いつ」「何を」「どうなる」を省かない。
- ルールの節には、使うコンポーネントと、その節ですること（アクター）を明記する（RDRA の「関係でつなぐ」）。
- 1文を短くする。箇条書きを使ってよい。
- 改行コードは LF。
