# 体制の進化ログ

> **3行で**
> 1. 進め方の変更を「候補 → 評価 → 採用／却下」の型で記録する。却下も消さずに理由とともに残す。
> 2. 運用（誰が書き、誰が裁定するか）は [体制の進化](improve.md) が正。
> 3. 新しいものを上に書く。足したら、減らしたものも書く。

記録するのは進め方（手順・書き方・スキル・仕組み）の変更で、ゲームの設計の判断は `docs/decisions/` に書く。

このログが長くなったら（目安300行）、年ごとか月ごとのページに分ける。

この仕組みは前のリポジトリ（CarTaGraphFantasy・CarTaGraphAdventure の `docs/process/evolution.md`）から持ち込んだ。それより前の経緯はそちらにある。

## 書き方

- **候補** — `- [ ] <候補> — <気づいた状況>（<日付>）`。評価したら「採用」か「却下」へ移す。
- **採用・却下** — `### <日付> <題>` の下に、内容・理由・反映先と、次の3つを書く。新しいものを上に。
  - **きっかけ** — 誰が・何で気づいたか（ふりかえり／試遊／作業中の失敗／人間の要望）
  - **止め方** — どう防ぐか（仕組み／手順・書き方／置き場所）
  - **減らしたもの** — 足した分、何を減らしたか（[体制の重さの上限](improve.md#体制の重さの上限)）

## 採用

### 2026-11-01 ページの冒頭に3行のまとめを置き、進め方を分ける

読み物のページの冒頭の説明文を、`> **3行で**` のまとめに置き換えた（[書き方](writing.md)「ページの冒頭」）。103行あった `process/index.md` を、全体像と設計の順番だけにし、設計サイクル（`cycle.md`）・体制の進化（`improve.md`）・AI との協働（`ai.md`）に分けた。

- 反映先 … `docs/` の読み物のページ全部、`docs/process/`、`.claude/skills/`（参照先）、`AGENTS.md`
- **きっかけ** — 人間の要望（「はじめに」が長い。まず概要をつかみ、詳細は続きを読む形にしたい） ／ **止め方** — 書き方（冒頭のまとめ）と置き場所（ページを分ける）
- **減らしたもの** — 各ページの冒頭の説明文（まとめに置き換えた）。`docs/process/` の行数はまとめの分だけ増えた（上限400行に対して約240行）

### 2026-11-01 「はじめに」で読む順を示す

`docs/start.md` を置き、初めての人・間が空いた人が読む順と、AI との進め方の要点を1ページにした。中身は書き写さず、各ページへの道案内だけにする。ビューアに目次（`docs/_sidebar.md`）を足し、`docs/index.md` の冒頭から案内した。

- 反映先 … `docs/start.md`、`docs/_sidebar.md`、`docs/index.md`、`AGENTS.md`「ディレクトリ」
- **きっかけ** — 人間の要望（間が空いて戻ったとき、新人が入ったときに、どの順で把握すればよいか分かるように） ／ **止め方** — 置き場所（道案内の1ページ）
- **減らしたもの** — `AGENTS.md` に書いたビューアの動かし方を `docs/start.md` へ移した。`docs/process/` の行数は増えない

### 2026-11-01 スマホから docs を読めるようにする

- 反映先 … `docs/index.html`、`AGENTS.md`「ディレクトリ」
- **きっかけ** — 人間の要望（C1 で、進め方をスマホから読んで確かめたい） ／ **止め方** — 置き場所（ビューア1ファイル）
- **減らしたもの** — なし（`docs/process/` の行数は増えない。ビューアは Markdown を読むだけで、書き方の決まりを増やさない）

### 2026-11-01 体制を作り直す（ボードゲームとして先に設計する）

前のリポジトリ（CarTaGraphFantasy・CarTaGraphAdventure）で、小さな機能ごとに8手順の開発サイクルを回し、ゲームの全体像が決まる前に1シーンずつ作っていたため、進みが見えにくく、文書と検査が膨らんで把握しづらくなった。新しいリポジトリで、外側（コンセプト）から内側（ルール → モデル → 実装）へ設計しきる形に作り直した。

- 反映先 … このリポジトリ全体
- **きっかけ** — 人間の要望（前のリポジトリで進みが出ず、ステップを刻みすぎていると感じた） ／ **止め方** — 置き場所（新しいリポジトリ）と手順（設計の順番・終える条件・重さの上限）
