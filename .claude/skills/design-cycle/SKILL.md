# 設計サイクル

手順の本文は `docs/process/cycle.md` が正。ここは呼び出し口なので、手順を書き写さない。

## 始めるときに読むもの

1回の応答でまとめて読む。

- `docs/index.md` … いまのフェーズと、終える条件のどれが残っているか
- `docs/questions.md` … まだ決めていない問い
- `docs/cycles/` の最新の記録 … 前のサイクルの「次に試すこと」
- `docs/design/vision.md` … デザインの柱（判断の物差し）
- `docs/process/writing.md` … どこに何を書くか

## 進め方

1. 最新の記録の状態が「進行中」「答え待ち」なら、新しく作らず、その続きから始める。「終わり」なら、次の番号でサイクルの記録 `docs/cycles/<日付>-C<番号>-<題>.md` を `docs/cycles/index.md` の型で作る。今回の問いの束の案を、目指す終える条件とともに人間に示して選んでもらう。
2. 詰めるときは `grilling` スキルを使う。
3. 決めたら、`docs/design/` に結論、`docs/decisions/` に理由と採らなかった案を書き、`docs/questions.md` から決めた問いを消す。
4. ふりかえりを書き、進め方の気づきは `docs/process/evolution.md` の候補に足す。終える条件を満たしたと思うものは、根拠を添えて人間にチェックを頼む（AI はチェックを付けない）。
5. 人間の答えを待って止まるたびに、記録を書いてコミットする（`docs/process/cycle.md`「止まるたびに記録へ書く」）。サイクルの終わりには、人間に結果と次のサイクルの候補を伝える。
